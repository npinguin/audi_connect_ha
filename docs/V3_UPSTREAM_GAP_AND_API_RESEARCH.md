## 5. Suggested engineering deliverables

- Build an incremental route comparison ledger: source repo/commit/license or vendor spec, API family/auth/market, method, semantic capability, response schema, existing catalog match, gap, confidence, permission, expected HA representation, and test result. Distinguish reference-only, reviewed read-only, and approved command.
- Prioritize one vertical slice at a time: read/discover → normalize → native HA entity → diagnostics → synthetic tests → actual vehicle acceptance → reviewed catalog contribution. No uncontrolled probes.
- Add community issue-to-capability traceability and a vehicle acceptance matrix. Review exact b15/current candidate separately from historical evidence.
- Keep research findings optional until a reviewed decision, verified authorization and evidence. Never poll a new provider merely because it exists. Avoid second active command ownership; charging hardware control and energy optimization belong to their respective systems.
- Consider a future sanitized contribution export/import and catalog review workflow; this is an enhancement, not a released capability or a new mandatory gate.

**Recommendation:** close current V3 upstream readiness while running P1/P2 research as a separate backlog on the canonical development stream. Do not turn the integration into a multi-brand framework or make commercial APIs a prerequisite for ordinary users.
